# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands
- `npm run dev` — Next.js dev server at http://localhost:3000
- `npm run build` — production build
- `npm start` — run built server
- MCP endpoint: `POST /api/mcp` (Streamable HTTP transport via `mcp-handler`)
- Quick MCP smoke test: curl an `initialize` request against `/api/mcp` (see README §MCP 테스트)
- No test runner configured; ad-hoc scripts live under `scripts/` and are run with `npx tsx scripts/<file>.ts`

## Architecture
`kr-valuation-data` (formerly KICPA Beta MCP / DCF-Peergroup-Search). Web-based MCP server (Next.js 15 + `mcp-handler`) deployed to Vercel serverless. Exposes financial data tools built on OpenDART (corporate filings/financials, pre-collected per quarter-end) and the FSC stock/index price APIs on data.go.kr (prices, market cap, beta — fetched per request with the **caller's own key**, never stored).
- **Market data rule (2026-10-31)**: FSC price datasets (15094808 stock, 15094807 index) are license type 4 — no third-party redistribution. Never write prices, market caps or betas into `data/`, Blob, or any shared cache; compute them per request from the caller's `datagokr_key` (query → `x-datagokr-key` header, `src/services/market/fsc.ts`). The `DATA_GO_KR_API_KEY` env fallback is for self-hosting only — never set it on the public deployment.
- Naver Finance scraping is off on the public server (Naver ToS forbids automated collection). `naver_get_market_data` registers only when `KVD_ENABLE_NAVER=1` (self-hosting).

Request flow:
1. `app/api/[transport]/route.ts` — single MCP handler that registers all tools.
2. `src/services/tools/*.ts` — one file per MCP tool; each defines a zod input schema and delegates to a service client.
3. `src/services/{opendart,market,naver}/` — upstream API clients. `market/fsc.ts` builds adjusted closes from raw close + `vs` (change vs the exchange's adjusted base price): chaining `clpr/(clpr−vs)` matched the old Naver-based betas to 5-6 decimals. FSC data starts 2020-01-02 (Monthly-5Y gets 60 points only from 2025). `kicpa/types.ts` is a shared type file only (KICPA lookup path removed).
4. `src/services/common/` — shared resolvers, notably the stock-code → DART `corp_code` mapping backed by `data/corp-codes.json`.
5. `src/services/utils/` — shared error handling and response formatting.

Key tools:
- `valuation_get_data` is the composite tool — quarter-end cache (or live DART) for financials + caller-key FSC prices for price/beta (`withMarket` always overwrites any market fields left in cache files), so changes to any upstream client must preserve its expected output shape. Without a key it returns financials with `market.error` explaining how to add one.
- `peergroup_get_population` is the deterministic peer-population tool — it reads only the immutable quarter-end snapshots in `data/peer-snapshot/*.json.gz` (business overview + segment revenue + exclusion flags per company) and never falls back to live APIs. Same (valuation_date, industry_code) input must always return the same population; the response includes a `populationHash` for audit reproducibility. Never add a live fallback to this tool.

Caches and builders (all under `data/`, loaded via `process.cwd()`-relative paths — any new cache file must also be added to `outputFileTracingIncludes` in `next.config.ts` or it will be silently missing on Vercel):
- `data/corp-codes.json` — regenerated by `scripts/update-corp-codes.ts` (DART `corpCode.xml`).
- `data/company-industry.json` — `scripts/update-industry-data.ts`; per stock: KSIC `industryCode` (DART) + `market`/`accMonth`/`listedDate` (KRX KIND, no API key needed).
- `data/valuation-cache/{quarter-end}.json` + `.meta.json` — `scripts/collect-valuation-cache.ts <YYYYMMDD…> | --latest`. Financials and DART share counts only; `beta`/`marketCap.price`/`total` are always null in the files (stripped 2026-10-31). With `DATA_GO_KR_API_KEY` the collector uses that date's listed shares only to fix DART unit errors.
  Financials use the **latest periodic report filed as of the valuation date** (`src/services/opendart/report-asof.ts`, same rule as the peer snapshot).
  Interest-bearing debt uses **IBD engine v2** (`ibd-engine.ts`): balance-sheet face rows, section by the 유동부채/비유동부채 header rows (never by name substrings),
  XBRL note supplement when borrowings are bundled into "금융부채" (`xbrl-debt-facts.ts`), financial-industry exclusion, debt-like items split out.
  Shared logic for the collector and the live tool path lives in `src/services/valuation/asof-financials.ts`.
  Policy (what counts as IBD, categories, partial/hold rules): `docs/IBD_POLICY.md` — keep engine and policy in sync.
  Engine is now v2.3: XBRL '공시금액'(ReportedAmountMember) contexts, lease-from-notes when the face has no lease row, note-total residual fill, `completeness: "partial"` when debt may be missing.
  Raw store: `data/valuation-cache/_shared/raw/{date}/{rcept}.json.gz` (BS/IS rows + XBRL facts + shares, gitignored) — recompute without DART;
  bumping `IBD_ENGINE_VERSION` makes the collector recompute every report (offline when raw exists).
  Independent verification tools (DART-heavy, run locally): `ibd-corpus.ts` (all-company raw), `ibd-notes.ts` (note text for a sample),
  `ibd-crosscheck.ts`, `ibd-sample.ts` (tuning/holdout), `ibd-gold.ts` (compare engine vs blind-audit gold labels, export gold fixtures).
  Regression: `npm run test:ibd` (fixtures in `tests/fixtures/ibd` + `tests/fixtures/ibd-gold`, expectations in `tests/ibd-expected.json`, synthetic rule cases). Quality gate: `scripts/check-valuation-cache.ts`.
- Data files are read through `src/services/cache/data-files.ts` (bundle first, then Vercel Blob at `KVD_BLOB_BASE_URL`); `data/manifest.json`
  (`scripts/build-data-manifest.ts`) lists dates that exist only in Blob. Upload with `scripts/upload-data-blob.ts`.
- Automation: `.github/workflows/collect-quarterly.yml` (quarter-end collection, resumable across DART daily limits via actions/cache) and
  `refresh-reference.yml` (weekly corp codes / industry). LLM summaries (`summarize-peer-snapshot.ts`) stay manual.
- `data/business-cache/{year}.json.gz` — `scripts/collect-business-cache.ts` (full "사업의 내용" markdown).
- `data/peer-snapshot/{quarter-end}.json.gz` — `scripts/collect-peer-snapshot.ts`; run shortly after each quarter-end (build lag loses delisted companies). Section slicing lives in `src/services/opendart/section-slicer.ts`; as-of report selection in `document-parser.ts` (`fetchBusinessContentAsOf`). After collecting, run `scripts/summarize-peer-snapshot.ts <date>` to add `overviewSummary`/`segmentsSummary` (LLM via `claude -p`, frozen once generated) and `segmentsBrief` (deterministic revenue-table slice, fallback) — `peergroup_get_population`'s default `content_mode="summary"` reads these fields (segmentsSummary → segmentsBrief → full text).

Other files under `scripts/` are one-off diagnostics (`test-*`, `analyze-*`).

Peer-group agent workflow (which tool at which step) is defined in `docs/PEER_GROUP_WORKFLOW.md` — tool descriptions route LLMs there, so keep it in sync when changing tool behavior.

## Environment
- `OPENDART_API_KEY` — required for `dart_*` and `valuation_get_data` tools
- Caller's data.go.kr key — `?datagokr_key=` or `x-datagokr-key`, for price/market cap/beta. `DATA_GO_KR_API_KEY` env only for self-hosting / the collector's share check.
- `KVD_ENABLE_NAVER=1` — self-hosting only, registers `naver_get_market_data`
- Smoke test: `npx tsx --env-file=.env.local --env-file=<file with DATA_GO_KR_API_KEY> scripts/smoke-market.ts`

## Conventions
- TypeScript strict, ESM, Node ≥18
- Tool inputs validated with zod; throw via shared error helpers in `src/services/utils/` so MCP responses stay consistent
- Korean comments and log messages are intentional — preserve language when editing
